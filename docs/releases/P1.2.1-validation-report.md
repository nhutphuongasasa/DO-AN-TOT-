# P1.2.1 – Burst Integration Verification Report

## Scope

This verification pass checks the existing P1.2 Burst integration, the PCAP replay
entry point, Burst export arguments, lifecycle behavior, and regression coverage.
It does not claim live-NIC acceptance or ML model evaluation.

## Change made

- Fixed the `appid-pcap-replay` CLI so `--burst-jsonl` and `--burst-tsv` are
  forwarded to `replay_pcap()`. The replay function already supported both output
  paths, but the CLI previously parsed the flags and then failed to pass them on.
- Added a regression test that invokes the CLI entry point and asserts both export
  paths and the session/network arguments reach `replay_pcap()`.

## Skipped acceptance tests and limitations

1. Real Scapy PCAP integration – skipped because Scapy is not installed in this
   build environment. Installing it was attempted, but package-index access was
   unavailable. The real-PCAP path therefore remains to be verified on the target
   Linux machine with project dependencies installed.
2. Scapy DNS parser test – skipped for the same missing Scapy dependency.
3. Live NIC integration – intentionally skipped; it requires
   `APPID_RUN_LIVE_NIC_TEST=1`, root privileges, and a suitable Linux interface.

## Acceptance commands for the target Linux machine

```bash
./setup_linux.sh
.venv/bin/python -m pytest -q -rs
.venv/bin/python -m pytest -q tests/integration/test_pcap_burst_pipeline.py
sudo env APPID_RUN_LIVE_NIC_TEST=1 .venv/bin/python -m pytest -q tests/integration/test_live_nic_linux.py
```

The live-NIC test is opt-in and should only be run when the configured interface
and capture permissions are understood. A successful unit/integration suite in
this build environment is not a substitute for these target-machine checks.

## Status

P1.2.1 code verification is partially complete: the CLI export defect is fixed
and covered by regression tests, and the available suite passes. Full target
acceptance remains pending the real Scapy-PCAP and, where applicable, live-NIC
checks above.
