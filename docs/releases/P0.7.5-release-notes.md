# P0.7.5 — TCP SNI acceptance tooling

## Changes

- Added `scripts/generate_tcp_test_traffic.sh` to issue five HTTPS requests
  explicitly with HTTP/1.1 over TCP and bypass environment-configured proxies.
- Added `run_tcp_appid_test.sh` to capture TCP/443 on one selected NIC, produce
  a traffic report, optionally inspect TCP TLS SNI with tshark, and replay the
  same PCAP through the shared PacketProcessor.
- Enhanced PCAP replay flow output to include AppID, identification method and
  reason code, so a replay can be checked per TCP flow rather than by counters
  alone.
- Added the P0.7.5 live acceptance procedure and criteria.

## P0.7.5.1 corrective update

- Fixed Ethernet PCAP decoding by initializing Scapy's link-layer registry
  (`scapy.all`) before constructing `PcapReader`. This addresses replay output
  where all Ethernet frames were previously counted as unsupported Raw data.
- Changed capture cleanup to signal `tcpdump` with SIGTERM so background
  capture is stopped and the PCAP is flushed without hanging on ignored SIGINT.
- Added a regression assertion that the Scapy layer registry is initialized
  before the PCAP reader is constructed.
- Recorded the user's 2026-11-24 live evidence: all five target HTTP/1.1
  requests returned HTTP 200 and `tshark` observed all five target TCP SNI
  hostnames. PacketProcessor acceptance remains pending a successful replay.

## P0.7.5.2 corrective update

- Replaced the background `tcpdump` capture process in
  `run_tcp_appid_test.sh` with `dumpcap` and a TCP/443 capture filter.
- Capture shutdown now sends SIGINT to `dumpcap`; this was verified on the
  target Ubuntu environment, where `dumpcap` exited with status 0 and flushed
  its PCAP. The prior SIGTERM failure was traced to an AppArmor signal denial
  against the `tcpdump` profile (`peer="vscode"`).
- Added a 180-second hard capture limit (`CAPTURE_MAX_SECONDS` can override it),
  signal-aware cleanup, capture exit-status checks and unique temporary logs.
- Packet generation, optional tshark SNI inspection and PacketProcessor replay
  remain in the same workflow.
- Build validation for this package: `python3 -m pytest -q` — 122 passed,
  2 skipped; `bash -n` passed for both shell scripts. These checks do not
  establish live capture acceptance; the revised runner must still be exercised
  on the user laptop.

## Scope and limitations

This release adds test tooling and makes PCAP replay output more auditable; it
does not change TCP reassembly, TLS parsing, DNS correlation or QUIC behavior.
HTTP/1.1 probe completion is not proof of SNI extraction or AppID success.
The live acceptance remains open until PCAP evidence confirms all five target
hostnames and PacketProcessor classifies the corresponding TCP flows.

## P0.7.5.3 corrective update — dumpcap output and script permissions

### P0.7.5.2 defects addressed

- Shell scripts were not consistently executable in the ZIP. In particular, `run_tests.sh` was stored as `0600`, preventing direct invocation.
- `run_tcp_appid_test.sh` wrote its active PCAP directly to the final project path instead of staging it under `/tmp` until capture shutdown was complete.

### Changes

- Set every project `.sh` file to mode `0755` and preserve Unix mode bits in the ZIP entries.
- Stage each capture in a unique `/tmp/p075-tcp-capture-*` directory.
- Stop `dumpcap` with SIGINT after traffic generation and always `wait` for the process before validating or publishing the PCAP.
- Require the temporary PCAP to exist and be non-empty, then move it to the requested output path and set final mode `0644`.
- Add EXIT/INT/TERM cleanup that stops and waits for an active `dumpcap` process and removes temporary capture/log artifacts.
- Preserve the 180-second default hard capture limit and leave AppID, DNS, TCP, TLS, UDP, QUIC, evidence, and replay implementation code unchanged.

### Validation

See `docs/releases/P0.7.5.3-validation-report.md` for the recorded check results. Static checks and the automated test suite are run during packaging. Live capture on the user's laptop is explicitly **not claimed** by the build-environment checks and must be repeated there using `sudo ./run_tcp_appid_test.sh <interface>`.

## P0.7.5.4 corrective update — strict TCP/SNI acceptance

- Added `scripts/verify_tcp_appid_acceptance.py` to validate the traffic report
  and replay the final PCAP through the shared PacketProcessor API.
- The live runner now exits non-zero if the PCAP is absent/header-only, a probe
  failed, packets were not parsed/tracked, unsupported/packet parse errors are
  present, or any of the five target TCP SNI AppIDs is missing.
- Each expected app must be represented by a TCP Flow whose identification
  method is `sni` or `hybrid_dns_sni` and whose `tls_sni` evidence exactly matches
  the expected hostname.
- HTTP response success is explicitly treated as probe evidence, not AppID proof.
- `sni_parse_errors` is printed for diagnosis but is not a hard failure by itself;
  target-flow SNI evidence is the acceptance criterion.
- Added unit tests for complete acceptance, missing targets, invalid transport/
  identification method, and failed probe reports.
- The user's P0.7.5.3 laptop evidence showed 2,541 captured packets, zero capture
  drops, all five target SNI names and five target AppIDs in replay. The new
  strict gate has not yet been run on that laptop; packaging checks do not claim
  a P0.7.5.4 live acceptance result.
