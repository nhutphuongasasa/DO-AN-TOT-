# P0.7.3 — QUIC v1 Initial Parsing

## Added

- QUIC v1 Initial long-header parser and QUIC variable-length integer reader.
- RFC 9001 Initial key derivation using Python `cryptography` and the v1 salt.
- AES header-protection removal, packet-number reconstruction and AES-128-GCM
  authentication/decryption.
- Initial frame parsing for PADDING, PING, ACK/ACK_ECN, CRYPTO and connection
  close frames.
- Bounded, per-sender CRYPTO stream reassembly with overlap and memory limits.
- Reuse of the existing TLS ClientHello parser to extract visible SNI and
  preserve ECH detection metadata.
- RFC 9001 client Initial key-schedule vector test and deterministic encrypted
  packet fixtures.

## Dependencies

`cryptography>=42.0,<47.0` is added to `pyproject.toml` and `requirements.txt`.

## Scope boundary

- QUIC v1 Initial only; QUIC v2 is intentionally not accepted.
- No 0-RTT/1-RTT keys or application payload decryption.
- No ECH inner hostname recovery.
- No UDP Flow / PacketProcessor / live NIC / PCAP integration; planned P0.7.4.
- No shared live/PCAP `PacketProcessor` mapping in this phase. The added offline PCAP helper can apply the existing explicit SNI domain rules after extracting SNI; it does not provide live pipeline integration.

## HTTP/3 traffic generation and offline verification tools

- `generate_quic_test_traffic.sh` / `scripts/generate_quic_test_traffic.py`
  generate forced HTTP/3-only requests for ChatGPT, Facebook, TikTok, YouTube
  and Spotify. The script reports PASS only for curl HTTP version 3 and writes
  `quic-traffic-report.json`.
- `scripts/inspect_quic_initial_pcap.py` uses Scapy and the P0.7.3 QUIC v1
  Initial code to extract visible SNI from a UDP/443 PCAP and apply the existing
  SNI domain rules.
- Full steps: `docs/testing/quic-http3-live-test.md`.
- In this build environment, curl 8.10.1 advertises `--http3-only`; no real
  HTTP/3 request or live capture was performed. The PCAP helper was syntax
  checked but not exercised because Scapy is absent.


### Generator backend correction — 2026-11-24

- The first test-tools package used `curl --http3-only`. User validation showed
  Ubuntu curl 8.5.0 exposed the option text but its installed libcurl was not
  built with HTTP/3.
- Replaced that backend with `aioquic` so the project virtual environment can
  generate HTTP/3 directly without requiring a custom curl build.
- The new client offers HTTP/3 ALPN and QUIC v1 only, validates TLS certificates,
  and does not fall back to TCP/HTTP2. It still requires outbound UDP/443 and
  the target service to accept the client.
- Runtime/live validation remains pending on the user's laptop; the build
  container could not download aioquic because external package DNS was blocked.
