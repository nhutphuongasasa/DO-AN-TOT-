# P0.6.3–P0.6.5 — TCP SNI AppID Integration

## Delivered

- Added `src/appid/sni/identifier.py` to map normalized SNI names using the
  existing reviewed `ApplicationDomainRules` from `config/dns_mapping.yaml`.
- Integrated the existing `TCPReassembler` and `TLSClientHelloParser` into the
  shared `PacketProcessor` used by both live capture and PCAP replay.
- Inspected only the Flow's client-to-server direction; no port-based direction
  inference was added.
- Added bounded per-Flow ClientHello accumulation (64 KiB), reassembly idle
  cleanup, and cleanup on terminal parse / Flow close.
- Added SNI counters to live and PCAP summaries.
- Added `HYBRID_DNS_SNI`: DNS+SNI agreement retains both evidence sources;
  conflicts prefer SNI and preserve the DNS conflict in metadata.
- Kept the five named application labels and did not turn `other-web` into a
  catch-all domain rule.
- Added `docs/architecture/tcp-sni-appid-integration.md` and this release note.

## Tests

- Baseline before changes: `python3 -m pytest -q` → 85 passed, 2 skipped.
- After integration: `python3 -m pytest -q` → 88 passed, 2 skipped.
- `python3 -m compileall -q src tests` → passed.
- Scapy is not installed in this isolated build environment, and network access
  to install dependencies was unavailable. Therefore Scapy-specific DNS packet
  fixtures and opt-in live-NIC capture remain skipped/not run here. The new
  SNI-to-pipeline tests use packet/record doubles and do run in this environment.

## Acceptance still required on target laptop

Run `./setup_linux.sh`, `./run_tests.sh`, then run live capture with the chosen
NIC and generate HTTPS requests to each target service. Confirm the summary
shows SNI parsed/identified counts and inspect Flow IDs. This build does not
claim real-NIC acceptance or successful SNI observation for all five services.

## Limitations

- Visible TLS SNI only; no TLS decryption or ECH inner-name recovery.
- No UDP/QUIC identification in this release.
- Mid-stream capture may miss the ClientHello.
- Unmapped SNI remains unclassified; `other-web` is reserved for a later model
  or explicit classification policy.
