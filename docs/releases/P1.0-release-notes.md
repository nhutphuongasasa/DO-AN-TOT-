# P1.0 — ML Candidate Gate + Immutable Flow Observation Adapter

**Date:** 2026-11-24  
**Baseline:** P0.7.5.4

## Implemented

- Added `appid.ml.candidate_gate` with `ELIGIBLE`, `PENDING`, and `REJECTED` decisions and stable reason codes.
- Added explicit `FlowObservationPolicy`; minimum packet count and duration are never guessed.
- Added frozen, payload-free `FlowObservation` and `PacketObservation` snapshots.
- Reused `FlowTracker` / `FlowState` identity and client-relative direction; no second Flow ID is created.
- Added `PacketProcessor.evaluate_ml_candidate()` as the integration point after DNS/SNI processing.
- DNS/SNI-classified Flows exit the ML path. One-way Flows are retained with quality flags.
- Duplicate packet indexes remain pending because the deduplication policy is still open.

## Not in scope

- Bidirectional reconstruction beyond the existing FlowTracker metadata snapshot.
- Burst segmentation, feature extraction, CatBoost, 1D-CNN, Late Fusion, and inference.
- Choosing project-wide minimum observation thresholds.

Automated validation: **140 passed, 2 skipped** (`python -m pytest -q`); `compileall` passed; ZIP integrity check passed. Ruff was not available in the build environment. See `docs/testing/p1.0-ml-candidate-gate.md` for test coverage.
