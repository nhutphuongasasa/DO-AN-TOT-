# P0.7.4 — Hybrid TCP + UDP AppID integration

## Implemented

- Connected UDP structural protocol identification and QUIC v1 Initial
  inspection to the shared `PacketProcessor` used by live NIC capture and PCAP.
- Kept TCP reassembly/SNI and DNS parsing paths intact.
- Added bounded QUIC Connection/CID tracking, with independent UDP Flow and
  QUIC Connection identities and observed Initial-CID linkage across UDP tuples.
- Added QUIC SNI evidence mapping using the existing domain rules and explicit
  DNS agreement/conflict reason codes.
- Added UDP idle expiry and active UDP Flow capacity enforcement.
- Added per-stage UDP/QUIC counters to live capture and PCAP summaries.
- Added independent `enable_udp_analysis` / `enable_quic_analysis` controls.

## Validation in build environment

- Full regression: **122 passed, 2 skipped**.
- `python -m compileall -q src tests`: PASS.
- Shell syntax checks for test and traffic scripts: PASS.
- Scapy-dependent DNS parsing and opt-in live NIC tests remain skipped because
  Scapy is not installed in this build environment.
- No live NIC capture or fresh PCAP replay was run in this build environment.

## Known limitations

- QUIC v1 Initial only; no v2, Retry, 0-RTT/1-RTT or HTTP/3 payload decoding.
- No ECH inner hostname recovery.
- CID tracking covers authenticated Initial CIDs; no 1-RTT
  NEW_CONNECTION_ID processing and no claim of complete QUIC migration support.
- `QUIC_INITIAL` is a transport/application-protocol observation, not proof of
  a completed HTTP/3 request.
- User-laptop P0.7.3 PCAP evidence remains prior-phase evidence. P0.7.4 needs a
  fresh run with this integrated package to verify live UDP/QUIC pipeline
  counters and five-app AppID output.
